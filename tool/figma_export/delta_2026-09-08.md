# Built 2026-09-09

## Mood checker

Rebuilt as the design draws it: one illustration over a slider from "Awful" to
"Awesome", with an "Add Detail" button. The 3x3 emoji grid and `MoodTile` are
gone.

Layout is pinned to points measured off the frame, below the app bar: heading
44, figure 154 (203 tall), slider track centre 464, labels 489, button 570.
Slider colours sampled from the render — active `#638FE8`, inactive `#DADADA`,
handle and end labels `#2F6FED`.

**Four steps, two characters.** The artwork changes in bands at 20%, 45% and
70% of the track — read off where the design parked the handle for each
illustration, not even quarters. The male set has only three distinct faces
across its four frames, so its top two steps share one; the female set has
four. Which character shows comes from the KYC "What is your gender?" answer;
anything that is not an explicit "male" gets the female set, because it is the
only one drawn for all four steps.

**The data model changed.** `Mood` (nine named moods) became a `score` of 0..1
on `MoodEntry`, with `MoodLevel` derived from it. `MoodEntry.fromJson` still
reads the old `mood` key and maps it onto the scale, so an upgrading user
keeps their calendar and streak instead of losing them.

**Artwork extraction.** `/nodes` was rate-limited, so the illustrations could
not be exported as their own nodes. They were recovered from the rendered
frames instead: the same pose exists over a light `#F5FBFF` ground and a dark
`#1A1A1B` one at identical pixel positions, which makes alpha exactly
solvable — `(1-a) = (C_light - C_dark) / (B_light - B_dark)`, then
`F = (C_light - (1-a)B_light)/a`. Keying against one background alone left a
light halo on the female afro. Files are `assets/images/mood/{male,female}_*`.

**Open:** "Add Detail" has no frame behind it — no note composer is drawn for
this flow anywhere in the file. It commits the score and continues to the
records screen, which is where the old flow ended. If it is meant to open the
journal composer, say so.

## AI Hub (built 2026-09-09)

`176:56425` (Unexpanded) and `176:56395` (Expanded | Chat), reached from the
floating assist button — which until now raised "not built yet".

**One screen, two states**, not two routes. The frames are the same scene and
the collapsed one says so: "Tap Droplet or Chat to Expand".

Collapsed: the scene panel over three readouts (Vibe / Breathing Pace / Ease
Level), a rule, "Select Environment Vibe" as a three-way segmented control
(Sunset Calm / Morning Mist / Evening Breeze) and "Breathe Together".
Expanded: the same scene full-bleed behind the Wellness Guide conversation,
with a live dot, a close button and an "Ask anything..." composer.

Measured below the status bar: panel 52 (233 tall), readouts 314, rule 371,
section label 400, segments 421 (40 tall), button 485 (52 tall). Colours
sampled from the render — stat caption `#72737A`, value `#1B1F26`, rule
`#EBF1F5`, segment track `#FEFEFE` inside `#EAEAEA`, chosen segment
`actionFill`.

### The scene is painted, not exported

The frames bake "Tap Droplet or Chat to Expand" into the artwork, so a crop
would carry a label that cannot be changed, localised, or removed once the
panel expands. It is a `CustomPainter` instead: a sky gradient sampled down
the frame's left edge, three wave bands with hairline crests, a horizon glow,
and the droplet as a halo, a radial-filled egg, a hairline outline and a
highlight. That also gives the droplet its bob, which is what the guide's own
copy asks the user to breathe along with.

Two mistakes worth remembering:

- Sizing features as fractions of the *box* stretched the egg into a tall thin
  oval once the chat took the whole screen. Everything is in design units
  (341.5x233) now.
- Scaling to *cover* then ballooned the droplet to a quarter of the screen.
  The frames keep it the same size in both states, so the scene scales by
  width and anchors its waterline to the same fraction of the box, letting the
  sky grow instead.

### Open

- The readouts "4.7mm" and "94.2%" are session telemetry with no breathing
  engine behind them, so they are fixed strings. Only Vibe is live.
- Sending a message appends the user's line and says the guide is not
  connected. No model is wired, and a canned reply would look like an answer.
- The frame repeats one guide line as filler for its lower bubbles; that is
  mock copy, so only the two real opening lines are seeded.

## Notifications (built 2026-09-09)

`176:24737`, reached from the bell on Home — which had a `GestureDetector`
with no `onTap` at all, a dead control on every build until now.

The file has two notification frames. `176:36688` puts every entry in an
identical outlined card; `176:24737` is the mixed one and is the one built.
Its rows are deliberately different shapes, so each is a `NotificationKind`
and the list renders whichever it is handed:

| kind | shape |
|---|---|
| `social` | avatar, bold actor, rest of the line, timestamp |
| `reminder` | outlined card: red dot, icon, "Reminder", body line |
| `digest` | red dot, filled heart, heading, centred body — no border |
| `plain` | line with no avatar, timestamp |
| `action` | line, an inline "Read" link, timestamp |

Measured below the status bar: header 36, chips 99 (20 tall, radius 10),
first row 148, content margin 24. Chips — chosen one filled `#2F6FED`, the
others outlined `#ECEDED`. Reminder card border `#E6EBEE`. Unread dot
`#F45A4F`, 7.5. The title and the "Read" link are painted with the app's
existing `titleGradient`, which is what the sampled `#1E396E` turned out to be.

### Decisions

- **Timestamps are computed from a `DateTime`**, not stored strings. The frame
  writes "45minutes ago", "1 days ago" and "7minutes" — typos, and a stored
  string would be wrong the second time the screen opened. `AppNotification.ago`
  formats them properly, and the repository takes an injectable `now` so the
  goldens do not go stale by the hour.
- One consequence: "45 minutes ago" is ~11 wider than the frame's
  "45minutes ago", so the first row ellipsises at "commented on yo...". The
  source text is truncated post content ending in "..." anyway; correct
  spelling was worth the character.
- The frame writes "1 day ago" for Paul and "Yesterday" for John, both a day
  old. One formatter gives both "Yesterday".
- The reminder still says **Yoga**. The rename covered the three section
  names, not the practice, and this frame post-dates it.
- "Read" has nothing behind it — the Article frame (`176:30889`) is in the
  file but not built — so it says so.

### Assets

`/nodes` is still rate-limited, so the two avatars, the reminder glyph and the
solid heart were cropped from the render and keyed to transparent, as the mood
and profile art were. The frame gives Kendrick and Paul the same portrait, so
there are two avatars, not three. Both glyphs are navy line art from a
light-mode frame and are tinted at runtime, or they vanish on the dark palette.

## Gender before the concerns carousel (2026-09-11)

The questionnaire now opens on "What is your gender?" and the concerns
carousel is second. The order matters, not just the content: the carousel
draws a gendered figure, so the answer has to exist by the time that step is
reached. `KycOption.illustrationFor(gender)` picks the set; only an explicit
"male" switches, everything else — female, non-binary, undisclosed, no answer
— draws the female figure, the same rule the Mood Checker uses.

**Both sets are in.** The male carousel is a new row of four frames at y=0
(`191:36092`-`191:36125`), same grounds and accents as the female set; the
figures were lifted with `tool/extract_figure.py` as before. One thing to
know: the designer labelled his first frame "Stressed" where hers says
"Stress". The option label is gender-neutral and stays "Stress".

Test fallout was instructive: five tests assumed step 0 was `concerns` and
called `choose()` on it while the controller sat on `gender`, quietly writing
the concern under the gender key. They step through explicitly now, and the
golden test looks its steps up by id so a bare index cannot point at the
wrong screen again.

## Ten moods, named by the design at last (2026-09-26)

The file gained a `Recommendation | <mood>` frame for each of ten moods, and
a `Mood checker/male/ Awful`. That settles the vocabulary question left open
on 2026-09-09: the scale was four levels with two of the names ours, because
the frames only labelled the ends. It is now ten, all named, each with its own
line of copy.

| # | key | label | opens with |
|---|---|---|---|
| 1 | awful | Awful | "Ah, today feels heavy..." |
| 2 | drained | Drained | "You're running on empty, huh?..." |
| 3 | anxious | Anxious | "Brain moving a million miles an hour?..." |
| 4 | low | Low | "Some days just feel a bit gray..." |
| 5 | neutral | Neutral | "Just coasting through the middle today?..." |
| 6 | reflective | Reflective | "In your head today, huh?..." |
| 7 | content | Content | "Sitting pretty and at peace today?..." |
| 8 | energized | Energized | "Okay, look at you!..." |
| 9 | joyful | Joyful | "You're glowing today!..." |
| 10 | awesome | Awesome | "Absolute top form today!..." |

Copy was read from the frames' own text nodes rather than off a render, so it
is exact. The frame's tab for #5 reads "Neutra" — a truncation; the word is
Neutral.

The bands are ten even tenths now. The old four had *measured* thresholds
(0.20 / 0.45 / 0.70) because the frames parked the handle in four particular
places; with ten named stops an even split is what the slider can express.

### Artwork

Ten moods per figure are designed; twenty files are coming. Four female and
three male exist, so `MoodFigure._drawn` maps each mood to its nearest
exported neighbour, keeping the extremes honest — awful and awesome always
draw their own face. **Delete `_drawn` and its map when the twenty land**;
`artFor` then resolves each mood to its own art with no other change.

Two existing files were renamed to match the new keys: `female_good` →
`female_content`, `male_good` → `male_awesome`. A rename inside `assets/`
does not invalidate Flutter's asset manifest — the tests failed with "asset
does not exist" until `pubspec.yaml` was touched.

### Test lesson

Five assertions pinned a score to a level by name ("0.8 is awesome"). Those
broke the moment the bands moved, and would break again. They assert position
on the scale now — `level.index`, `MoodLevel.values.last`,
`representativeScore` — so the next change to the scale does not rewrite them.

## The expert application's uploads are real now (2026-09-26)

"Add file" (`259:59198`) was a stub. It opens the system document picker,
limited to the "(PDF, JPG, or PNG)" the frame asks for.

- **`file_picker`**, and the *document* picker rather than an image-library
  one: it needs no runtime permission on either platform, and a certificate
  is usually a PDF anyway.
- **The path is kept, not the bytes.** `withData: false` — a passport scan
  should not sit in memory across three form steps.
- **The picker is injectable.** `FilePicker` has no test implementation, so
  `ExpertApplicationController` takes a `DocumentPicker` function and falls
  back to the real one.

- **It only draws the empty chip.** Once a document is picked the chip gives
  way to a row naming it with its size and a way to drop it — a slot still
  reading "Add file" after a successful pick would be telling the applicant
  their certificate did not take.
- **Cancelling is not removing.** Backing out of the sheet leaves whatever was
  already in the slot.
- **10 MB.** The frame gives no limit; a phone photo of a certificate is 3-5
  MB and anything far past that will not upload on the connections these
  users have. The refusal names the file and its size.

**Both uploads are now required.** Their asterisks are the only thing on any
step of this form that marks anything mandatory, and until the picker existed
there was nothing to require.

### A test note worth keeping

`Get.testMode = true` does **not** suppress `Get.rawSnackbar`, and
`AppFeedback` only skips when `Get.context` is null — which it is not inside a
mounted `GetMaterialApp`. A test that triggers feedback has to pump past the
snackbar's own 3s dismiss timer or it fails with a pending timer.
